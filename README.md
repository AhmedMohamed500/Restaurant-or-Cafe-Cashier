# RestaurantFlow POS

نظام كاشير وإدارة مخزون وتصنيع وتكلفة للمطاعم والكافيهات، بواجهة عربية كاملة واتجاه RTL. يغطي النظام دورة التشغيل من تعريف وحدات القياس والمواد وحتى تصنيع المنتجات وبيعها وطباعة إيصال العميل.

## روابط المشروع

- الموقع المباشر على Sites: [restaurantflow-pos-eg.ahmed-mohamed206207.chatgpt.site](https://restaurantflow-pos-eg.ahmed-mohamed206207.chatgpt.site)
- الموقع المباشر على Vercel: [restaurant-or-cafe-cashier.vercel.app](https://restaurant-or-cafe-cashier.vercel.app)
- مستودع GitHub: [AhmedMohamed500/Restaurant-or-Cafe-Cashier](https://github.com/AhmedMohamed500/Restaurant-or-Cafe-Cashier)

## فكرة النظام

RestaurantFlow يربط المخزون بالوصفات والتصنيع والكاشير في دورة واحدة مترابطة. لا يتم تعديل الرصيد مباشرة من الجداول؛ كل إضافة أو خصم تمر من خلال حركة مخزون مسجلة بمرجع وتاريخ وتكلفة.

دورة التشغيل الأساسية:

```text
الوحدات
  ↓
المواد
  ↓
المخازن
  ↓
الوصفات
  ↓
التصنيع
  ↓
حركات المخزون
  ↓
التكلفة
  ↓
الكاشير والإيصال
```

## الوحدات الرئيسية

### 1. وحدات القياس

- إنشاء وحدات الوزن والحجم والعدد.
- تعريف الرمز والكود والاسم العربي والإنجليزي.
- تحديد معامل التحويل مقابل أصغر وحدة في العائلة.
- حماية الوحدة المستخدمة من الحذف للحفاظ على سلامة البيانات.

### 2. المواد والمنتجات

- إنشاء مواد خام، أصناف تحت التشغيل، ومنتجات تامة.
- تسجيل الكود والتصنيف والوحدة الأساسية والحد الأدنى والتكلفة.
- تحديد سعر البيع للمنتجات التي ستظهر في الكاشير.
- إضافة صورة للمادة أو المنتج بصيغ JPG أو PNG أو WebP.
- ضغط الصورة تلقائيًا قبل حفظها لتقليل استهلاك مساحة المتصفح.
- عرض الصورة في دليل المواد والمخازن والوصفات والتصنيع والحركات والكاشير.

### 3. المخازن

- إنشاء أي عدد من المخازن وربط كل مخزن بمرحلة مخزنية.
- عرض الأصناف المناسبة لنوع المخزن حتى لو كان رصيدها صفرًا.
- عرض صورة الصنف والكود والتصنيف والكمية ووحدة القياس.
- حساب قيمة المخزون بناءً على الكمية ومتوسط التكلفة.
- إدخال الرصيد الفعلي من شاشة الرصيد الافتتاحي بدل تعديل الجداول يدويًا.

### 4. الوصفات

- ربط المنتج الناتج بمكوناته وكميات كل مكون.
- اختيار وحدة وكمية الناتج.
- حساب تكلفة الوصفة تلقائيًا من متوسط تكلفة المكونات.
- دعم نسب الهالك والمكونات الاختيارية في نموذج البيانات.
- استخدام الوصفة عند التصنيع وعند البيع من الكاشير.

### 5. التصنيع

- إنشاء أمر تصنيع من وصفة مسجلة.
- تحديد عدد الدفعات والكمية الفعلية.
- اختيار مخزن صرف المكونات ومخزن إضافة الناتج.
- التحقق من توافر الرصيد قبل التنفيذ.
- خصم المدخلات وإضافة الناتج وتسجيل الحركات داخل معاملة واحدة.
- حساب إجمالي تكلفة الأمر وتكلفة وحدة الناتج والهالك.

### 6. حركات المخزون

- رصيد افتتاحي.
- مشتريات ضمن نموذج الحركة.
- صرف مكونات التصنيع.
- إضافة ناتج التصنيع.
- خصم مكونات المبيعات.
- تسويات وهالك ضمن أنواع الحركة المدعومة.
- تسجيل رقم المرجع والتوقيت والكمية وتكلفة الوحدة والقيمة الإجمالية.

### 7. التكلفة

- حساب تكلفة كل وصفة وتكلفة وحدة الناتج.
- مقارنة التكلفة بسعر البيع.
- حساب قيمة الربح وهامش الربح.
- عرض قيمة المخزون وآخر تكلفة إنتاج.

### 8. الكاشير

- كروت منتجات كبيرة ومناسبة للمس.
- صورة بارزة تظهر كاملة دون قص داخل مساحة عرض كبيرة.
- إضافة المنتج إلى الطلب بضغطة واحدة.
- تعديل الكمية أو حذف البند بخفض الكمية إلى صفر.
- حساب الإجمالي الفرعي والضريبة والإجمالي النهائي.
- طرق دفع: نقدي، بطاقة، ومحفظة إلكترونية.
- التحقق من مخزون مكونات الوصفة قبل اعتماد البيع.
- خصم مكونات الوصفة من المخزن النشط الموافق لنوع كل مكون.

### 9. إيصال البيع

بعد الضغط على «تحصيل» ينشئ النظام فاتورة مدفوعة ويعرض إيصالًا يحتوي على:

- اسم RestaurantFlow والفرع الرئيسي.
- رقم الطلب.
- التاريخ والتوقيت.
- نوع الطلب وطريقة الدفع.
- الأصناف والكميات وسعر الوحدة وإجمالي كل بند.
- عدد الأصناف وإجمالي الكميات.
- الإجمالي الفرعي والضريبة 14% والإجمالي النهائي.
- زر لطباعة الإيصال بمقاس مناسب لطابعة إيصالات 80mm.
- زر «طلب جديد» لإغلاق الإيصال والبدء بسلة فارغة.

- إزالة زر الإجراء المكرر من بطاقة الإرشادات في كل قسم.

- اعتماد تصميم أبيض نظيف مع رمادي فاتح وأزرق للعناصر النشطة.
- ربط المستودع بـVercel للنشر التلقائي عند تحديث فرع `main`.

## بداية الاستخدام الصحيحة

1. أضف وحدات القياس مثل جرام، كيلوجرام، لتر، ملليلتر، وقطعة.
2. أضف المواد الخام والتجهيزات والمنتجات التامة.
3. أضف مخزنًا لكل مرحلة مستخدمة: خام، تحت التشغيل، ومنتج تام.
4. أدخل الرصيد الافتتاحي لكل صنف مع تكلفة الوحدة.
5. أنشئ وصفة لكل منتج واربطها بالمكونات والكميات.
6. نفذ أوامر التصنيع إذا كان المنتج يحتاج تجهيزًا مسبقًا.
7. راجع الحركات والتكلفة وهامش الربح.
8. افتح الكاشير، أضف المنتجات، اختر الدفع ثم اضغط «تحصيل».
9. اطبع الإيصال أو أغلقه للبدء في طلب جديد.

## التخزين والنسخ الاحتياطي

هذه النسخة Demo محلية وتعتمد على IndexedDB من خلال Dexie:

- البيانات محفوظة داخل المتصفح وعلى نفس الجهاز.
- إعادة تحميل الصفحة لا تمسح البيانات.
- متصفح أو جهاز آخر يمتلك قاعدة بيانات مستقلة.
- لا توجد حاليًا قاعدة بيانات مركزية مشتركة بين الأجهزة.
- صور المنتجات محفوظة مع بيانات الأصناف داخل قاعدة المتصفح.
- زر «نسخة احتياطية» يصدر البيانات والصور في ملف JSON.
- زر «مسح كل البيانات» يعيد مساحة العمل إلى حالة فارغة.

> لا تستخدم «مسح كل البيانات» قبل تنزيل نسخة احتياطية إذا كانت لديك بيانات مهمة.

## مخطط البيانات

| الجدول | المحتوى |
|---|---|
| `units` | وحدات القياس والتحويل |

## تشغيل المشروع محليًا

المتطلبات:

- Node.js `22.13.0` أو أحدث.
- npm.

التثبيت والتشغيل:

```bash
git clone https://github.com/AhmedMohamed500/Restaurant-or-Cafe-Cashier.git
cd Restaurant-or-Cafe-Cashier
npm install
npm run dev
```

افتح العنوان المحلي الذي يظهر في الطرفية.

## النشر

### GitHub وVercel

## حدود النسخة الحالية

- البيانات ليست مشتركة بين عدة أجهزة أو مستخدمين.
- لا توجد حاليًا شاشة دخول أو صلاحيات متعددة.
- اسم المطعم في الإيصال ثابت حاليًا باسم RestaurantFlow.
- نسبة الضريبة في الكاشير ثابتة حاليًا عند 14%.
- النسخة الاحتياطية قابلة للتصدير، لكن استيرادها لم يُنفذ بعد.
- لا توجد حاليًا إدارة موردين أو فواتير مشتريات كاملة.

# RestaurantFlow POS

نظام Restaurant ERP عربي RTL يجمع المخزون والتصنيع والكاشير والمحاسبة والموارد البشرية للمطاعم والكافيهات. تظل دورة التشغيل في خمس خطوات بسيطة، بينما يعمل قسم المالية كطبقة قيود مزدوجة مرتبطة بنفس العمليات.

## دورة التشغيل

```text
المخزون → المطبخ → التصنيع → المنتج التام → الكاشير
```

### 1. المخزون

- إنشاء المادة وتنفيذ إذن الإضافة من شاشة واحدة.
- الوحدات المتاحة داخل الإذن: جرام، كيلوجرام، وعدد.
- تخزين الكمية داخليًا في الوحدة الأساسية مع الاحتفاظ بالكمية والوحدة اللتين أدخلهما المستخدم.
- حساب متوسط التكلفة والقيمة وتسجيل المرجع والتاريخ والملاحظات.
- لا يسمح بتعديل الرصيد مباشرة.
- يعرض جدول المخزون رصيد المخزن الرئيسي ورصيد المطبخ جنبًا إلى جنب لكل مادة، ويتحدث الرقمان تلقائيًا مع التحويل والتصنيع.

### 2. المطبخ

- المطبخ مخزون مرحلي وليس مصدرًا لكمية جديدة.
- التحويل يخصم من المخزن الرئيسي ويضيف إلى المطبخ بنفس التكلفة.
- تنشأ حركتا صرف واستلام مرتبطتان بنفس المرجع داخل transaction واحدة.
- يمنع التحويل فوق الرصيد أو بين عائلة الوزن وعائلة العدد.
- يعرض سجل تحويلات المطبخ «الرصيد الحالي» المتبقي لكل مادة، ويُحدّث بعد كل أمر تصنيع حتى عند وصول الرصيد إلى صفر.

### 3. التصنيع

- مكونات التصنيع تُختار من رصيد المطبخ فقط.
- قائمة وحدة سحب كل مكوّن ثابتة وواضحة: كيلوجرام، جرام، عدد؛ ويحوّل النظام تلقائيًا بين الكيلوجرام والجرام، بينما يمنع خلط وحدات الوزن بالعدد لحماية الرصيد والتكلفة.
- الجرام هو الاختيار الافتراضي لمكونات الوصفة، وكل وزن يُحفظ نهائيًا بالجرام؛ لذلك `1.5 كجم` تُسجل وتُخصم كـ`1500 جرام`، كما تُحوّل الوصفات القديمة تلقائيًا دون مسح البيانات.
- يدعم السحب بالجرام أو الكيلوجرام أو العدد حسب عائلة المادة.
- يخصم جميع المكونات، ويحسب التكلفة، ويضيف الناتج إلى المنتج التام في transaction واحدة.
- تعرض رسالة العجز اسم المكون والمطلوب والمتاح والعجز.

### 4. المنتج التام

- يظهر تلقائيًا بعد نجاح التصنيع.
- يعرض الصورة والرصيد والتكلفة وسعر البيع وربح الوحدة وهامش الربح.
- يسمح بتعديل سعر البيع دون تغيير تكلفة التصنيع.
- الرصيد لا يتغير من البطاقة؛ يزيد بالتصنيع ويقل بالبيع فقط.

### 5. الكاشير

- يعرض المنتجات التامة فقط، بصور كاملة باستخدام `object-fit: contain`.
- يمنع البيع بأكثر من الرصيد المتاح.
- عند التحصيل يخصم المنتج التام فقط؛ لا يعيد خصم مكونات التصنيع.
- مكونات الوصفة تكون قد خُصمت بالفعل بالجرام عند تنفيذ أمر التصنيع؛ لذلك لا يكرر الكاشير خصمها عند البيع، ويخصم فقط عدد المنتج التام لمنع الخصم المزدوج.
- يدعم النقدي والبطاقة والمحفظة الإلكترونية.
- ينشئ فاتورة مدفوعة وحركة بيع وإيصالًا قابلًا للطباعة بمقاس 80mm.

## الحسابات

- دليل حسابات مطاعم هرمي كامل: الأصول والالتزامات وحقوق الملكية والإيرادات وتكلفة المبيعات والمصروفات والإيرادات الأخرى.
- محرك قيود مزدوجة مركزي يمنع حفظ أي قيد غير متوازن، ويمنع القيم السالبة أو وجود مدين ودائن في نفس السطر.
- المشتريات النقدية والآجلة والجزئية والمرتجعات مرتبطة بالمخزون الرئيسي وبنفس المرجع المحاسبي.
- الموردون، الأرصدة الافتتاحية، السداد، الرصيد الجاري، والخزينة أو البنك المستخدم في الدفع.
- مصروفات المطاعم مع حساب المصروف وضريبة المدخلات والحساب المدفوع منه.
- الخزينة الرئيسية وخزينة الكاشير والبنك وتسوية البطاقات والمحافظ، مع تحويلات داخلية لا تعامل كإيراد أو مصروف.
- ورديات الكاشير وحساب النقد المتوقع والفعلي، مع قيد آلي لعجز أو فائض الكاشير عند الإغلاق فقط.
- القيود اليومية، القيد العكسي، الأستاذ العام، ميزان المراجعة، الأرباح والخسائر، المركز المالي، وتقرير VAT.
- لوحة ربحية تعرض المبيعات ومجمل وصافي الربح وتكلفة الطعام وهامش الربح والمخزون والموردين والنقد والبنك.

### القيود التلقائية

| الحدث | مدين | دائن |
|---|---|---|
| فاتورة مشتريات | مخزون خام + VAT مدخلات | نقد/بنك أو موردون |
| تحويل للمطبخ | مخزون المطبخ / تحت التشغيل | مخزون المواد الخام |
| إتمام التصنيع | مخزون المنتج التام | مخزون المطبخ / تحت التشغيل |
| بيع الكاشير | خزينة الكاشير/تسوية بطاقة/محفظة + تكلفة المبيعات | إيراد المبيعات + VAT مخرجات + مخزون المنتج التام |
| مصروف | حساب المصروف + VAT مدخلات | الخزينة أو البنك |
| سداد مورد | الموردون | الخزينة أو البنك |
| تحويل داخلي | الحساب المستلم | الحساب المحول منه |
| عجز وردية | مصروف عجز الكاشير | خزينة الكاشير |
| فائض وردية | خزينة الكاشير | إيراد فائض الكاشير |

مكونات الوصفة تخصم مرة واحدة فقط عند التصنيع. بيع المنتج يسجل تكلفة المنتج التام ولا يعيد خصم الدقيق أو الجبن أو أي خامة.

## الموارد البشرية

- دليل موظفين يحتوي على الكود والاسم والوظيفة والهاتف والراتب الأساسي وتاريخ التعيين والحالة.
- سجل حضور وانصراف يومي للحضور والغياب والإجازة، مع وقت الدخول والخروج والساعات الإضافية.
- مسير رواتب شهري يحسب الصافي من الراتب الأساسي والإضافي والمكافآت والخصومات والسلف.
- متابعة حالة الراتب: معلق أو مدفوع، وملخص لحضور اليوم ورواتب الشهر.

## الوحدات الداخلية

تُنشأ الوحدات الأساسية تلقائيًا ولا تظهر كخطوة مستقلة:

| الوحدة | العائلة | المعامل الأساسي |
|---|---|---:|
| جرام | وزن | 1 |
| كيلوجرام | وزن | 1000 |
| عدد | عدد | 1 |

`1 كيلوجرام = 1000 جرام`. لا يمكن تحويل العدد إلى وزن أو العكس. يمكن مثلًا إضافة 10 كجم دقيق وتحويل 750 جم للمطبخ ليصبح رصيد المخزن 9.250 كجم.

## المراحل المخزنية الداخلية

| المرحلة | قيمة النموذج الحالية | الاستخدام |
|---|---|---|
| المخزن الرئيسي | `raw` | استلام المشتريات |
| المطبخ | `work_in_progress` | مخزون مرحلي للتصنيع |
| المنتج التام | `finished` | مخزون جاهز للبيع |

تُنشأ المخازن الثلاثة تلقائيًا. أبقينا القيم القديمة في نموذج TypeScript لحماية بيانات المستخدمين الحاليين.

## قاعدة البيانات والمigration

- قاعدة البيانات: `RestaurantFlowPOS` باستخدام Dexie وIndexedDB.
- ارتفع إصدار schema إلى 4 دون مسح البيانات، وأضاف دليل الحسابات والقيود والموردين والمشتريات والنقد والورديات.
- تضيف migration بيانات الحركة الأصلية ومخزن المصدر والوجهة للحركات القديمة عند توفرها.
- تهيئة التطبيق لم تعد تمسح الجداول؛ تضيف فقط الوحدات والمخازن الأساسية الناقصة.
- كل تحويل وتصنيع وبيع يعمل داخل transaction ذرية لمنع حفظ نصف العملية.

راجع [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md) للتفاصيل.

## التقنيات

- Next.js 16 وReact 19 وTypeScript.
- Dexie 4 وIndexedDB للتخزين المحلي.
- Vinext وVite لبناء نسخة Sites.
- CSS عربي RTL متجاوب.
- هوية بصرية حمراء دافئة مناسبة للمطاعم والكافيهات، مع خلفيات بيضاء وألوان حالات هادئة وواضحة.
- خط المشروع بالكامل هو `Tahoma Bold` بحجم أساسي `12px`، مع `11px` للنصوص الصغيرة والجداول، لعرض كثيف وواضح مناسب لشاشات الكاشير.
- الصور تُضغط إلى WebP داخل المتصفح وتُحفظ مع الصنف.

هذه نسخة محلية Demo: البيانات محفوظة داخل نفس المتصفح والجهاز وليست مشتركة بين عدة أجهزة. يمكن تصدير نسخة JSON تشمل التشغيل والفواتير والمصروفات والموظفين والحضور والرواتب وصور المنتجات. استيراد النسخة الاحتياطية وقاعدة البيانات المركزية ضمن التطوير القادم.

## اسم المطعم والشعار وتسجيل الدخول

- عند أول فتح يطلب النظام اسم المطعم واسم المستخدم وكلمة المرور، مع شعار اختياري.
- يظهر اسم المطعم وشعاره في القائمة والإيصال، ويمكن تعديلهما من «إعدادات المطعم».
- كلمة المرور لا تُحفظ كنص واضح؛ تُحفظ بصمة SHA-256 داخل IndexedDB.
- جلسة الدخول تستمر داخل تبويب المتصفح، ويوجد زر خروج واضح.
- عند نسيان اسم المستخدم أو كلمة المرور يمكن اختيار «نسيت بيانات الدخول؟»، ثم كتابة اسم المطعم المسجل وتعيين بيانات دخول جديدة. العملية تغيّر بيانات الدخول المحلية فقط ولا تمس المخزون أو الوصفات أو الحركات أو الفواتير.
- الخاصية مجانية تمامًا ولا تعتمد على خدمة خارجية أو اشتراك.

> هذه حماية محلية لنسخة Demo على نفس الجهاز والمتصفح، وليست نظام حسابات مركزيًا. أي شخص لديه وصول فعلي لنفس المتصفح ويعرف اسم المطعم يمكنه إعادة تعيين بيانات الدخول. فتح الموقع من جهاز أو متصفح جديد ينشئ إعدادًا مستقلًا، ومسح بيانات الموقع يمسح بيانات الدخول المحلية.

## حدود النسخة الحالية

- لا توجد مزامنة بين الأجهزة أو صلاحيات مستخدمين متعددة.
- الضريبة ثابتة حاليًا عند 14%، بينما اسم المطعم والشعار قابلان للتعديل.
- تعريف المنتج والوصفة يسبقان حركة التصنيع؛ أما خصم المكونات وإضافة الناتج وأمر الإنتاج نفسها فذرية بالكامل.
- البيانات المالية محلية داخل نفس المتصفح؛ لا توجد مزامنة أو اعتماد قانوني/ضريبي أو إقفال فترات وموافقات متعددة المستخدمين بعد.
- فاتورة المشتريات تدعم عدة بنود، ووحدة وتكلفة وVAT مستقلة لكل بند.
- لا توجد بعد شاشة مطبخ وطاولات.
